- 现象: `text/tabwriter` 按 rune 数量算列宽。中文、日文、韩文这种 East Asian wide 字符实际占 2 列，导致含 CJK 的行后面的列往左偏，`all-cli status`、`all-cli current`、`all-cli catalog` 的表格对不齐。
- 想改成啥: 表格按终端显示宽度对齐。wide / fullwidth 字符算 2 列，其他字符算 1 列。纯 ASCII 表格的输出一个字节都不变。
- 验收:
  1. 纯 CJK 行、CJK + ASCII 混排行，每一列在所有行上的起始显示列相同（`internal/output/tabwriter_test.go`）。
  2. 纯 ASCII 表格的输出与原来的 `tabwriter.NewWriter(w, 0, 4, 2, ' ', 0)` 逐字节一致。
  3. 多字节字符被拆成多次 `Write` 时，输出与整行写入一致；内部 filler 不会出现在输出里。
  4. `just ci` 全绿（tidy、fmt、policy、vet、test、coverage ≥80%、golangci-lint）。
- In / Out:
  - In: `internal/output` 新增 `NewTabWriter`；`status`、`current`、`catalog`、`catalog` summary 四处 tabwriter 改用它；`golang.org/x/text` 从 indirect 改为 direct（版本不变，仍为 v0.14.0，无新依赖）。
  - Out: `all-cli docker list` 不走 tabwriter，它直接输出 `\t` 交给终端 tab stop，ASCII 行本身也不对齐，属于另一个行为改动，另开 Issue 处理。`doctor --fix` 的 `%-14s` 定宽输出同理。
